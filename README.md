# Планирование остановов станков на обслуживание

Прототип ПО для задачи планирования остановов оборудования. Станки работают
циклами из трёх этапов (ТО-1, ТО-2, ТР). Каждый этап заканчивается остановом
на обслуживание. Надо выбрать моменты остановов так, чтобы:

- наработка станка перед остановом была близка к плановой;
- соседние станки не стояли на обслуживании одновременно;
- загрузка ремонтных бригад была равномерной и не превышала их число R.

## Методы

| Код | Метод | Модуль |
|---|---|---|
| `milp` | MILP с индексацией по времени: модель на PuLP, решатель HiGHS | `msched/milp.py` |
| `milp_cbc` | Та же модель MILP, решатель CBC (встроен в PuLP) | `msched/milp.py` |
| `cpsat` | Модель программирования в ограничениях, Google OR-Tools CP-SAT | `msched/cpsat.py` |
| `h1` | Жадная эвристика H1 | `msched/heuristics.py` |
| `h1h2` | H1 + итерированный локальный поиск H2 | `msched/heuristics.py` |
| `ga` | Генетический алгоритм | `msched/ga.py` |

Все методы оценивают расписание одной функцией `msched/evaluate.py`.

## Математическая модель (кратко)

Время дискретное, шаг — сутки. Для останова a станка i заданы плановая
наработка r_a, длительность d_a и допустимое окно наработки [lo_a, hi_a].
Переменная s_a — момент начала останова. Фактическая наработка:
L_a = s_a − (s_prev + d_prev), для первого останова L_a = s_a.

Целевая функция:

    F = w_dev · Σ|L_a − r_a| + w_conf · (число конфликтов соседей)
      + w_peak · (пиковое число одновременных остановов)

Ограничения: L_a ∈ [lo_a, hi_a]; в каждые сутки идёт не больше R остановов.
Конфликт — пересечение остановов соседних станков с зазором δ
(режим `overlap`) или совпадение окончаний этапов ближе δ (режим `finish`).

## Установка

Нужен Python 3.10 или новее.

```
python -m venv .venv
.venv\Scripts\activate            (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
```

## Использование

Создать пример (размеры: S, M, L, XL):

```
python -m msched generate --size M --seed 1 -o instances/M_s1.json
```

Решить пример одним методом с лимитом времени 60 с:

```
python -m msched solve instances/M_s1.json -m cpsat -t 60 -o results/M_s1_cpsat.json
```

Сравнить все методы на примерах S, M, L (по 3 примера каждого размера):

```
python -m msched bench --sizes S M L --seeds 1 2 3 -t 60 --out results
```

Анализ чувствительности к параметру (например, к допуску наработки):

```
python -m msched sens --param tol --values 0.05 0.1 0.15 0.2 0.3 --size M -t 30
```

Параметры для `sens`: `tol`, `delta`, `sync`, `capacity`, `run_spread`,
а также веса ЦФ `w_conf`, `w_peak`, `w_dev`.

Полный набор экспериментов для отчёта (около 70 мин) и графики:

```
bash scripts/run_experiments.sh
python -m msched plots --results results --out figures
```

Пошаговая демонстрация всех методов на одном примере с диаграммой Ганта
и выгрузкой расписания в Excel: ноутбук `demo.ipynb`.

Запустить тесты:

```
python -m pytest
```

## Результаты

Команды `bench` и `sens` сохраняют в папку `--out`:

- `bench.csv`, `sens_<param>.csv` — все прогоны;
- `*_summary.csv` — средние по группам;
- `instances/` — примеры в формате JSON;
- `solutions/` — найденные расписания.

Столбцы таблиц:

| Столбец | Значение |
|---|---|
| `objective` | значение ЦФ |
| `gap_best_pct` | отклонение от лучшего решения на этом примере, % |
| `sum_dev`, `max_dev` | суммарное и максимальное отклонение наработки, сут |
| `conflicts` | число пар пересекающихся остановов соседей |
| `peak`, `load_std` | пик и СКО загрузки бригад |
| `overload`, `feasible` | превышение числа бригад и допустимость |
| `t_first`, `t_best`, `t_opt` | время до первого, до лучшего и до оптимального решения, с |
| `status` | `optimal`, `feasible`, `heuristic`, `unknown` |
